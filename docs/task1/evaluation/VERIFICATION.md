# Verification performed for the Task 1 evaluation add-on

## Limits

Only synthetic inputs were used. No real feature matrix, real outer-fold
prediction table, manuscript AUC/CI, full production-size workload or actual SHAP
source was supplied for these checks. Passing the comparisons below does not
validate the scientific correctness of the original study or establish its
historical software environment.

## Bootstrap: seven original/release pairs

Each pair was run with 5 folds, 20 proteins, 240 frames, both labels within each
protein, threshold ties, and tied scores. The default 2000 bootstrap replicates,
seed 42, confidence 0.95 and maximum-redraw setting 10000 were used.

Compared all original output CSVs: CI summaries, complete bootstrap distributions,
recomputed per-fold metrics and protein-label compositions. All pairs passed
`rtol = atol = 1e-12`; the observed maximum absolute difference was **0.0** for
all compared numeric columns. Input file checksums were unchanged. A repeated
release run targeting its populated output directory was rejected.

Additionally, all original statistical/validation function and class ASTs,
excluding the CLI parser and main orchestration function, were unchanged. The
single-class redraw failure branch and every possible invalid-input condition
were not exhaustively exercised.

## Preparation: four original/release pairs

The full synthetic schema comprised 433 feature columns (8 global scalars,
5 interfacial scalars, 210 residue-pair contacts, 210 residue-pair hydrogen bonds)
plus the group identifier and native 0/1 label. It contained 20 proteins and
240 rows, with a constant feature included.

Deletion counts were 8, 5, 210 and 210. Reduced tables had 425, 428, 223 and
223 feature columns, respectively. Each release table matched the corresponding
source-generated table in values and column/row order. The identifiers and
labels were retained. The input file checksum was unchanged, and overwriting a
prepared output was rejected. Filename differences for the two known legacy
mismatches were intentional and excluded from content equality.

## XGBoost ablation: four original/release pairs

First compared all default parameter values, search-space key order, baseline
parameter dictionaries, and complete sequences of 50 candidates for fold seeds
43, 44, 45, 46 and 47. All matched their uploaded originals.

The numerical execution checks used all 5 outer folds and final full-data
training, but reduced computation to 3 candidate settings per fold, a 60-tree
upper bound, 8-round early stopping, and one numerical/estimator thread for both
versions. These are **test-only settings**, not the published default settings.

Compared all generated CV, trial and prediction CSVs, per-fold best-parameter
JSONs, final best parameters, and final-model probabilities. All pairs passed
`rtol = atol = 1e-12`. The observed maximum absolute numeric difference was
**0.0**. Plots were generated by the retained code, but image pixels/layout were
not included in the numerical equivalence claim.

The published defaults remain 5 folds, 50 candidate settings, 3000 boosting
iterations as the upper bound, and 100-round early stopping. No full-scale
50-candidate/3000-tree run was performed on the research data.

## Interface and privacy checks

- All 15 entrypoints returned successful `--help` output when launched from
  outside the repository.
- Explicit paths were exercised from an external working directory; bootstrap
  and ablation dry runs did not create the requested output directory.
- Inspected the new successful-run JSONs for the deliberately external test-path
  prefix; none retained that directory prefix. Basenames remain present.
- Verified that released paths do not collide with files from the two previous
  training release ZIPs.
- Checked 15 original scripts, 16 published Python files and 11 JSON
  configurations for the listed credential/private-key/path/internal-network
  patterns. No matches were found. This was a heuristic review only and did not
  inspect unprovided files, real data, logs or repository history.

Exact observed versions are in `requirements-tested.txt`; machine-readable
comparison results and scope details are in `verification_results.json`.
No real datasets, synthetic fixtures, plots, trained models, internal test harness
or raw logs are included in the release archive.
